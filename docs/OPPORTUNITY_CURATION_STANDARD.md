# Opportunity Curation Standard — M6b Framework

## Status

This is a future team process, not a live job board. The production curated-source catalog is empty. No unverified real listing or source is displayed by M6b.

## Minimum approval evidence

Before a real curated source can appear, the team must record:

1. A reliable official source URL and its source type (university career centre, official employer careers page, public internship portal, or public job board).
2. The date it was checked, its country/location scope, and a clear role-family or audience label.
3. A concise reason it may be useful to the selected research-backed segment, without saying it is a match, endorsement, complete list, or current vacancy feed.
4. A named team approval decision and an active/inactive review state.
5. CP2 evidence supporting the chosen segment, the value of this source category, and the wording used to describe relevance.

## Review and removal

The approving team must recheck each active source at least every 30 days and after a user reports a broken or materially changed link. Mark a source inactive or remove it when it is unavailable, misleading, no longer reliable, no longer relevant to the documented audience, lacks current approval, or its supporting CP2 evidence no longer applies.

## Safe relevance language

Describe a source only by its recorded audience, role family, and location scope—for example, “a source to explore for the recorded audience.” Do not call it a personal match, recommended job, verified vacancy, endorsed source, comprehensive directory, or guaranteed-current opportunity.

## Explicit exclusions

The standard does not authorize scraping, crawling, API ingestion, external URL fetching by EXE, listing verification, employer account automation, or automatic recommendation. Any future real source requires the evidence above and explicit owner/team approval before display.
