# OwnPath OpenCode Factory

Four roles: Factory Lead, read-only Repo/Product Auditor, one Core Engineer writer, independent read-only QA/Security. Configuration is generated by `scripts/setup-ownpath-factory.mjs`; no extra Factory app, backend, model connection or dashboard exists.

OpenCode is **not installed in the Work container** (`command -v opencode` returned no path). No owner's machine/version was accessed. Version-specific agent and command templates are prepared, not claimed installed/running. No ZIP was attached to this turn, so no ZIP was copied or audited.

## Setup on the owner's development checkout

First preserve any local work. Fetch the feature branch, then create a separate worktree so your current checkout stays intact:

```bash
cd ~/EXE
git status -sb
git fetch origin
git worktree add ../OwnPath-Translator feat/ownpath-experience-translator
cd ../OwnPath-Translator
pnpm install --frozen-lockfile
opencode --version
node scripts/setup-ownpath-factory.mjs
node scripts/setup-ownpath-factory.mjs --write
opencode
```

If Git reports the branch is already checked out, use that worktree; do not reset or delete it. Setup dry run first detects actual `opencode --version`; only recognized 1.x or 2.x semantic versions are supported. It selects V1 `permission` maps versus V2 ordered `permissions` rules, creates four `.opencode/agents/ownpath-*.md` and four `.opencode/commands/ownpath-*.md`, and refuses differing existing files or symlink escapes. Other configs and root AGENTS.md are untouched. Repeated installation is idempotent for identical files. Unknown versions require doc review instead of guessing. CLI execution/loaded schema is an owner-local acceptance step, not established by unit tests.

The installer is deliberately not run with a simulated version to activate a guessed configuration. Generated files can be committed after runtime inspection. Check your global/provider/MCP settings and actual loaded permission display, because project profiles do not install or select models. Use your approved coding provider, and never include private project/JD data in a coding prompt.

Official docs checked 2026-10-12: [V1 agents](https://opencode.ai/docs/agents/), [V1 commands](https://opencode.ai/docs/commands/), [V2 agents](https://opencode.ai/v2/docs/agents), [V2 commands](https://opencode.ai/v2/docs/commands), [V2 permissions](https://opencode.ai/v2/docs/permissions). V2 uses different agent permission fields/actions. Commands contain no executable shell expansions or implicit file attachments.

## Work cycle

Select `ownpath-lead`, then use:

```text
/ownpath-audit
/ownpath-scope
/ownpath-build OP-11
/ownpath-verify
```

The build target must match actual BACKLOG dependency/gate state. OP-11 is next acceptance work once the synthetic slice passes code checks. Lead delegates audit/review read-only and exactly one writer. QA reads exact logs and diff. Lead/Engineer shell permission automatically allows only specific Git inspection commands. Executing package tests/builds prompts for owner approval because editable code can run arbitrary shell/file operations; review the current diff before permitting the check. Git mutations/deploys also prompt. Auditor/QA have shell/edit denied. Engineer edits only synthetic module/route and its issue docs/scripts; changing API/Auth/RLS, old modules or root config requires an updated authorized plan.

Read denies conventional env/PEM file patterns; content grep is disabled because a read-tool rule alone cannot protect other content-search tools. Use glob then permitted reads. Unknown tools, external directory, web fetching and MCP actions default deny. These permissions reduce accidental scope expansion; they do not prove arbitrary secrets are unreadable or replace a hardened sandbox. Owner-approved shell commands and local package scripts can have side effects. Review any new script before permitting it. Never blanket-enable auto approval to bypass the formal release/data gate.

## Gates / checkpoint evidence

A audit observed; B synthetic scope supplied but human CP2/production pending; C ADR proposed; D controlled feature tests; E independent QA plus browser/RLS evidence; F owner release. Write actual state in `docs/ownpath/STATUS.md`. Preserve failed attempts and clearly distinguish historical tests from fresh results. Backlog→audit→scope→one writer→tests→independent QA→draft PR→owner approval→merge/deploy is diagrammed in FLOWS.

No auto-created GitHub Issues, recruitment messages, merge or deployment. A draft PR supplies a concrete review surface. Human research stays with the team using RESEARCH_PLAN and existing CP2 records.
